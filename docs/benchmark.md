# 实测基准数据 (Benchmark)

本基准数据基于对中文工程标准规范文档（真实工程规程样本，42MB，200 页）在 macOS 环境下的实测记录。

---

## 1. 性能对比摘要

| 指标 | 方案 A：OpenDataLoader PDF (Fast 模式) | 方案 B：传统版面 OCR 引擎 / 多模态云端 | 差异幅度 |
|---|---|---|---|
| **处理总耗时** | **1.12 秒** (秒级瞬发) | 120 秒 ~ 600 秒 (视排队与并发而定) | **提速 100x+** |
| **产出文本量** | 145,321 字符 (约 77,200 汉字) | 约 76,000 ~ 77,500 汉字 | 相当 |
| **条文读序还原** | 严格符合左至右、章节递进顺序 | 偶有分栏跨栏串读 | Fast 表现更优 |
| **专有名词准确率** | **100% 原始文本还原**（零字符幻觉） | ~98.5%（偶发形近字识别错误） | Fast 零损耗 |
| **资源消耗** | 极低（纯 CPU 单线程流式解析） | 需 GPU / 显存 或高带宽上传 | Fast 极度轻量 |

---

## 2. 结论与工程指导

1. **有文本层文档（电子版规程、说明书）**：
   - 坚决走纯文本流式抽取。
   - 不仅在耗时上带来数量级的飞跃，更重要的是**根除了 OCR 对工程数字与英文代号的误识别**风险。
2. **纯扫描件与图像型 PDF**：
   - Fast 模式无效（输出 0 字节），此时必须无缝回退到版面识别模型（MinerU 等）。
