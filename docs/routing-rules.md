# 路由决策规则 (Routing Rules)

面向中文工程文档的 PDF 转 Markdown 处理，最核心的原则是：**「先探查、再分流，坚决避免无脑全量 OCR」**。

---

## 1. 引擎选型与定位

| 引擎类型 | 代表工具 | 核心优势 | 适用场景 | 风险与弱项 |
|---|---|---|---|---|
| **纯文本流式抽取** | OpenDataLoader PDF (fast) | 速度极快（秒级数百页）、读序符合中文条文阅读习惯、条文编号不丢失 | 具备清晰内嵌文本层的标准规范、技术规格说明书、论文 | 遇到纯扫描件静默输出 0 字节；嵌套列表层级易扁平化 |
| **版面多模态解析** | MinerU (本地 basic / 云端 standard) | 强大的版面切分、表格还原、公式提取、扫描件高保真还原 | 纯扫描件、双栏论文、图表混排报告、矢量/扫描混合图纸 | 本地加载需要显存/内存与冷启动时间；云端排队较慢 |
| **视觉模型兜底** | 多模态大模型 (Vision) | 能理解非标图纸、手写批注、复杂走线图与超复杂拓扑 | 局部解析失败页、关键图签核验、疑难图纸单独重试 | 成本高、单次调用上下文受限、无法大批量经济运行 |

---

## 2. 自动化判定逻辑与阈值

`tools/classify.py` 对每一页提取观测量，判定页面类型，再汇总为文档级结论。所有阈值集中在脚本顶部，修改时请同步本节。

### 2.1 采样方式

- **≤60 页全量逐页扫描**；更长的文档**在全文范围内均匀采样 15 页**（首页、末页必含）。
- 不再只看前 5 页：封面、扉页、目录页字很少，旧做法会把电子版规范误判为扫描件；后半本才出现的扫描附录也会被漏掉。
- 需要精确页段（混排文档拆分）时用 `--sample 0` 强制全量。

### 2.2 单页信号

| 信号 | 计算方式 | 用途 |
|---|---|---|
| 有效字符数 | 去空白后的字符数 | `< 50` 视为无有效文本 |
| 汉字数 | Unicode 基本区 + 扩展 A/B + 兼容区 | 统计口径，见坑 6 |
| 乱码率 | `U+FFFD`、`■□`、私用区 PUA、控制字符、`(cid:N)` 的占比 | `≥ 20%` 判为乱码文本层 |
| 图片覆盖率 | 页内图片面积 / 页面面积 | `≥ 60%` 视为扫描/图像页 |
| 隐形文本占比 | 渲染模式 3（invisible）文本对象占比 | `≥ 50%` 且图片覆盖高 → 扫描件 + OCR 文字层 |
| 图签区域强特征词 | 可视页面**右下角 45%×35%** 与**右侧 15% 竖条**内命中的强特征词数（已处理 `/Rotate`） | 图纸判定主信号 |
| 图幅 | 横向，或长边 ≥ 1100pt（约 A3 及以上） | 图纸辅助信号 |
| 矢量路径数 | 页面（含表单 XObject）中的 path 对象数 | `≥ 300` 为图纸辅助信号 |
| 句读密度 | 每百汉字中 `。；，、：` 的数量 | `≥ 4` 且汉字 ≥200 视为条文正文 |

### 2.3 工程图纸判定（计分制）

旧版"全页命中 ≥4 个关键词"会把**设计规范本身**判成图纸——"设计、审核、日期、专业、阶段"在规范正文里几乎每页都有。现在关键词分强弱两级，并结合位置与版式计分：

- 强特征词：`图号 图名 比例 审定 校核 会签 制图 描图 图幅 项目负责人 专业负责人 设计号 工程编号 子项 版次 出图日期`
- 弱特征词（只作辅助）：`设计 审核 日期 阶段 专业 工程名称 标段 建设单位`

| 条件 | 分值 |
|---|---|
| 图签区域内强特征词 ≥ 2 | +2 |
| 全页强特征词 ≥ 3，或强 ≥ 2 且弱 ≥ 3 | +1 |
| 横向或大图幅 | +1 |
| 矢量路径 ≥ 300 | +1 |
| 竖向普通幅面上的条文正文（句读密度高） | −2 |

**总分 ≥ 3 判为图纸页**，分流至视觉/版面分析模型。`--pages` 输出的 `signals` 字段会列出每页命中的加减分项，便于调参。

### 2.4 页面类型与引擎

| 页面类型 | 判定 | 推荐引擎 |
|---|---|---|
| `text` | 有效文本层，其余条件不满足 | `opendataloader-fast` |
| `scan` | 图片覆盖 ≥60% 且几乎无文字 | `mineru-ocr` |
| `scan_ocr_layer` | 图片覆盖 ≥60% 且文字为隐形 OCR 层 | `mineru-ocr`（可先 fast 预览） |
| `garbled` | 乱码率 ≥20% | `mineru-ocr` |
| `drawing` | 图纸计分 ≥3 | `mineru-layout-or-vision` |
| `vector_only` | 几乎无文字但矢量路径很多 | `mineru-layout-or-vision` |
| `blank` | 空白页 | 并入相邻页段 |

注意：整页铺了背景图（水印底图、扫描边框）但文字**可见**的电子版页面，按 `text` 处理并在 `signals` 中提示，不会被误送 OCR。

### 2.5 文档级汇总

- 非空白页中，次要引擎页数占比 ≥10% 或 ≥3 页 → `document_type: mixed`、`recommended_engine: split`，并输出 `segments`（1-based 闭区间，可直接用于 `qpdf --pages` 或 MinerU `--pages`）。
- 否则取主类型，少量异类页记入 `warnings`。

### 2.6 Hybrid 模式避坑警示

- 许多开源工具提供 `hybrid`（混合模式：在原有文本上补充 OCR）。
- **实测结论**：严禁在具有良好文本层的中文规范上启用 hybrid。它极易把原生的规范代号（如 `FAS` 识别为 `CFAS)`、书名号《》误转为 HTML 实体 `&gt;&gt;`），反而引入了不可逆的 OCR 噪音。`tools/qa_check.py` 会把残留的 HTML 实体标出来。

## 3. 长文档与批量拆分策略

- **单批次控制**：对于 MinerU 等重型解析任务，单批推荐控制在 **5 ~ 10 页**。
- **长文档分段**：对于超 200 页的整本技术规格书或规程，建议先按章节或按 50 页拆分为子 PDF 文件后串行推进。
- **混排文档**：按 `classify.py --sample 0` 给出的 `segments` 拆分，文本段走 fast、扫描段走 MinerU，最后按页码顺序合并。
- **失败页单独追踪**：记录每一页的转换状态 `[success, failed, empty]`。若偶发某页解析超时或解析截断，**仅单独重试该页**，不要整批重复提交，避免反复重排和资源浪费。
